# オンライン理解度テスト

小規模な社内向けの、時間計測付きオンラインテストです。
受験者はブラウザで回答し、結果は Google スプレッドシートに自動で保存されます。確認者はスプレッドシートを見るだけで結果を確認できます。

- 設定時間は**目安**です。時間を過ぎても強制終了・自動提出はせず、超過した時間を記録します。
- サーバーや有料サービスは使いません(GitHub Pages + Google Apps Script + Google スプレッドシート)。

```text
GitHub Pages (React + TypeScript + Vite)
   ├─ localStorage … 受験途中の回答・開始日時・受験状態
   └─ 提出 ──▶ Google Apps Script(採点・保存)──▶ Google スプレッドシート ──▶ 確認者
```

現在は**デザイン確認モード**です。トップページで 3 つのデザイン案を見比べられます。
デザインを 1 つに決めたあとの切り替え方法は「[17. デザイン変更方法](#17-デザイン変更方法)」を参照してください。

## セットアップ

### 1. 必要なもの

- Node.js 20 以上(npm を含む)
- Google アカウント(スプレッドシートと Apps Script を作成する人。確認者のアカウントが適しています)
- GitHub アカウント(GitHub Pages で公開する場合)

### 2. Spreadsheet作成

1. <https://sheets.new> を開き、新しいスプレッドシートを作成します。
2. 分かりやすい名前を付けます(例: `理解度テスト 回答`)。

シートや見出し行は自動で作られるので、中身は空のままで構いません。
このスプレッドシートは**受験者には共有しないでください**(共有するのは確認者だけ)。

### 3. Apps Script作成

1. 作成したスプレッドシートのメニューから **拡張機能 > Apps Script** を開きます。
2. 最初から入っている `コード.gs` の中身をすべて消し、このリポジトリの [`gas/Code.gs`](gas/Code.gs) の内容を貼り付けて保存します。

### 4. Apps Script設定

`Code.gs` の先頭にある「設定」を確認します。

| 項目 | 内容 |
|---|---|
| `SPREADSHEET_ID` | 保存先のスプレッドシート ID(次項) |
| `SHEET_NAME` | 保存するシート名(既定: `回答`。無ければ自動作成) |
| `ANSWER_KEY` | 選択式問題の正解 |
| `TEXT_QUESTION_IDS` | 記述式問題の問題 ID |
| `RETURN_SCORE` | 正解数を受験者の画面に返すか(既定: `false`) |

設定後、エディタ上部の関数選択で **`setup`** を選び **実行** します。
初回は権限の承認を求められるので許可してください。シートと見出し行が作成されます。

### 5. Spreadsheet ID設定

手順 3 のとおりスプレッドシートから Apps Script を作成した場合、`SPREADSHEET_ID` は**空のままで動作します**(紐づいているスプレッドシートに保存されます)。

別のスプレッドシートに保存したい場合や、<https://script.google.com> から単独でスクリプトを作成した場合は、URL の次の部分を設定してください。

```text
https://docs.google.com/spreadsheets/d/【ここがSpreadsheet ID】/edit
```

```js
const SPREADSHEET_ID = '1AbC...xyz';
```

### 6. Webアプリデプロイ

1. Apps Script エディタ右上の **デプロイ > 新しいデプロイ** を開きます。
2. 「種類の選択」(歯車)で **ウェブアプリ** を選びます。
3. 次のように設定して **デプロイ** します。
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**

> 「全員」にするのは、ログインなしで受験者のブラウザから回答を送れるようにするためです。
> この URL でできるのは回答の送信だけで、スプレッドシートの中身を読むことはできません。

**`Code.gs` を変更したとき(正解の変更など)は、デプロイ > デプロイを管理 > 編集(鉛筆)> バージョン「新バージョン」> デプロイ を行ってください。** 保存しただけでは公開中の Web アプリに反映されません。この方法なら URL は変わりません。

### 7. WebアプリURL取得

デプロイ完了画面に表示される **ウェブアプリの URL**(`https://script.google.com/macros/s/…/exec`)をコピーします。
ブラウザでこの URL を開き、`{"ok":true,"message":"online test endpoint is running"}` と表示されれば動作しています。

### 8. `.env`設定

`.env.example` を `.env` という名前でコピーし、URL を設定します。

```text
VITE_GAS_ENDPOINT=https://script.google.com/macros/s/xxxxxxxx/exec
```

- `.env` はローカル専用で、Git に含めない設定(`.gitignore`)になっています。
- 公開版(本番ビルド)用の URL は `.env.production` に書きます。こちらは Git で管理します(手順 11)。
- `VITE_` で始まる値はビルド後の JavaScript に埋め込まれ、誰でも見ることができます。**パスワードや秘密鍵などは絶対に入れないでください。**
- 未設定の場合は「デモ送信」となり、提出してもスプレッドシートには保存されません(デザイン確認用)。

### 9. ローカル起動

```bash
npm install
npm run dev
```

表示された URL(通常 <http://localhost:5173>)をブラウザで開きます。`.env` を変更したときは起動し直してください。

### 10. GitHubへPush

GitHub で空のリポジトリを作成し、次を実行します。

```bash
git init
git add .
git commit -m "オンラインテストアプリ"
git branch -M main
git remote add origin https://github.com/<ユーザー名>/<リポジトリ名>.git
git push -u origin main
```

### 11. GitHub Pages公開

`main` に Push すると自動でビルド・公開する設定([`.github/workflows/deploy.yml`](.github/workflows/deploy.yml))を同梱しています。

1. リポジトリの **Settings > Pages** を開き、**Source** を **GitHub Actions** にします。
2. プロジェクト直下の `.env.production` の `VITE_GAS_ENDPOINT` に、手順 7 の Web アプリ URL を設定してコミットします。公開版(本番ビルド)の送信先はこのファイルから読み込まれます。
3. **Actions** タブで `Deploy to GitHub Pages` を **Run workflow**(または `main` に Push)します。
4. 完了すると `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます。

> - GitHub の無料プランで GitHub Pages を使えるのは**公開リポジトリ**です(非公開リポジトリでの利用は有料プランが必要)。
> - 公開したページは URL を知っていれば誰でも開けます。問題文は見られても構わない内容にしてください(正解はページに含まれません)。

## 運用・変更方法

### 12. 問題追加方法

問題は [`src/data/questions.ts`](src/data/questions.ts) の配列で管理しています。ここに追加するだけで全デザインに反映され、画面のコードを直す必要はありません。

- `id` は重複しない番号にします(スプレッドシートの列名 `Q1` `Q2` … と対応します)。
- 配列の並び順が出題順です。
- 追加後、**Apps Script 側も必ず合わせて更新**します(下の 13・14)。

### 13. 選択問題追加方法

1. `src/data/questions.ts` に追加します。選択肢は上から A, B, C, D … として扱われます。

   ```ts
   {
     id: 11,
     type: "choice",
     question: "問題文",
     choices: ["選択肢A", "選択肢B", "選択肢C", "選択肢D"],
   },
   ```

2. `gas/Code.gs`(Apps Script エディタ上のコード)の `ANSWER_KEY` に正解を追加します。

   ```js
   const ANSWER_KEY = {
     // …
     11: 'C',
   };
   ```

3. Apps Script を新バージョンとして再デプロイし、フロント側も Push します。

### 14. 記述問題追加方法

1. `src/data/questions.ts` に追加します。`maxLength`(最大文字数)は省略できます(省略時は 1000 文字)。

   ```ts
   {
     id: 12,
     type: "text",
     question: "問題文",
     maxLength: 800,
   },
   ```

2. `gas/Code.gs` の `TEXT_QUESTION_IDS` に問題 ID を追加します。

   ```js
   const TEXT_QUESTION_IDS = [6, 7, 8, 9, 10, 12];
   ```

3. Apps Script を再デプロイし、フロント側も Push します。

問題を追加すると、スプレッドシートには新しい列が**右端に自動で追加**されます(既存のデータは動きません)。

### 15. 制限時間変更方法

[`src/config/testConfig.ts`](src/config/testConfig.ts) の `durationMinutes` を変更します。

```ts
durationMinutes: 30,
```

テスト名(`title`)や、完了画面に時間を表示するか(`showTimeSummaryOnComplete`)も同じファイルで変更できます。

### 16. 正解変更方法

Apps Script エディタで `ANSWER_KEY` を変更し、**新バージョンとして再デプロイ**します(手順 6 参照)。
正解は Apps Script 側にしか無いため、フロント側の変更・再公開は不要です。
すでに保存済みの行の正解数は再計算されません。

### 17. デザイン変更方法

**デザインを 1 つに決めて本番運用する場合**は、`src/config/testConfig.ts` を変更します。

```ts
designPreviewMode: false, // デザイン選択画面を出さない
defaultDesign: 2,         // 使用するデザイン (1 | 2 | 3)
```

これでトップページから直接テストが始まり、「デザイン選択へ戻る」と「デザイン確認ツール」は表示されなくなります。テストの処理はそのまま使われます。

**見た目を調整する場合**は、各デザインのフォルダだけを編集します。

| 場所 | 内容 |
|---|---|
| `src/designs/Design01/` `Design02/` `Design03/` | 各デザインのレイアウト(`index.tsx`)と色・形(`*.css`) |
| `src/styles/base.css` | 全デザイン共通の部品(選択肢・記述欄・タイマーなど)の基本形 |

色や角丸は各 CSS 先頭の変数(`--accent` `--radius` など)で変えられます。
タイマー・保存・提出などの処理は `src/hooks/` `src/services/` にあり、デザインとは分離されています。

### 18. Spreadsheet確認方法

スプレッドシートの `回答` シートに、**1 回の受験が 1 行**で追加されます。

| 列 | 内容 |
|---|---|
| attemptId | 受験ごとの識別子(二重登録の防止に使用) |
| 氏名 | 受験者が入力した氏名 |
| 開始日時 / 基準終了日時 | テスト開始時刻と、開始 + 設定時間 |
| 提出日時(端末) | 受験者の端末で提出ボタンを押した時刻 |
| 受信日時(サーバー) | Apps Script が回答を受け取った時刻(端末の時計に左右されません) |
| 所要時間 / 所要時間(秒) | 開始から提出までの時間 |
| 時間超過 | `あり` / `なし`(`あり` は薄い赤) |
| 超過時間 / 超過時間(秒) | 設定時間を超えた時間 |
| 選択式問題数 / 正解数 / 正答率 | 選択式の採点結果 |
| Q1, Q2, … | 選択式の回答(A〜D)。**不正解は薄い赤、未回答は灰色**の背景 |
| 記述1(Q6), … | 記述式の回答全文(採点はしません) |

日時はすべて日本時間です。フィルタや並べ替えは自由に使えますが、**見出し行(1 行目)の文字は変更しないでください**(列の対応に使用しています)。

通常「提出日時(端末)」と「受信日時(サーバー)」はほぼ同じです。大きく離れている場合は、送信に失敗して後から再送信した、または端末の時計がずれている可能性があります。

## 仕組み

### タイマーと超過時間

- 開始時に `startedAt`(開始日時)と `targetEndAt`(開始 + 設定時間)を保存します。
- 残り時間は毎回 `targetEndAt - 現在時刻` から計算します。カウンタを減らしているわけではないので、リロードしても、ブラウザを閉じて開き直しても、時間はリセットされず進み続けます。
- 現在時刻が `targetEndAt` を過ぎると「超過時間」の表示に切り替わります。回答・移動・提出はそのまま続けられ、自動提出はしません。
- 残り 10 分・5 分・1 分以下で、タイマーの色と枠が段階的に変わります(点滅はしません)。

### localStorage に保存する内容

| キー | 内容 | 削除のタイミング |
|---|---|---|
| `online-test:session:v1` | attemptId、氏名、startedAt、targetEndAt、現在の問題番号、回答(選択式・記述式)、表示中の画面、提出状態、提出日時 | **送信に成功したときだけ** |

回答は入力・選択のたびに保存されます。

### 提出後の自動ログアウト(同じ端末を複数人で使う場合)

- 提出(送信)に成功した時点で、氏名と回答を含む受験中データを端末から削除します。
- 完了画面の内容(所要時間など)は端末に保存していません。ページを開き直す、または完了画面の「最初の画面に戻る」を押すと、氏名入力の画面に戻り、次の人がそのまま受験できます。
- 送信に失敗した場合だけは、回答を失わないようデータを残します(再送信が成功した時点で削除されます)。
- 提出せずに途中でやめた場合は、受験中データが端末に残ります。共用の端末では、必ず提出まで行ってもらってください。

### 提出と二重送信対策

- 提出ボタンを押した時点で回答を固定し、以後は変更できません(送信に失敗した場合も同じ)。
- 送信中はボタンを無効にし、処理中の再実行も防いでいます。
- Apps Script 側でも `attemptId` を確認し、登録済みであれば追加しません(排他ロックにより同時に届いた場合も 1 件だけ登録)。そのため「再送信」や通信の再送で行が重複することはありません。
- 送信に失敗した場合、回答は端末に残り「再送信」できます。提出日時は最初に提出ボタンを押した時刻のままです。

### CORS への対応(採用方式と理由)

`fetch` で **`Content-Type: text/plain;charset=utf-8`**、本文は JSON 文字列として POST しています。

- `application/json` で送ると、ブラウザは事前確認(プリフライト、`OPTIONS` リクエスト)を送ります。Apps Script の Web アプリは `OPTIONS` に応答できないため、送信が失敗します。
- `text/plain` は「単純リクエスト」に該当し、プリフライトが発生しません。Apps Script 側は `e.postData.contents` を `JSON.parse` して受け取ります。
- 「アクセスできるユーザー: 全員」でデプロイした Web アプリの応答は別オリジンからも読み取れるため、`no-cors` を使わずに**成功・失敗を判定**できます(成功を確認できたときだけ端末の回答を削除するために必要です)。
- `application/x-www-form-urlencoded` も同じく単純リクエストですが、入れ子のデータ(回答の配列)を扱いにくいため採用していません(Apps Script 側は `payload` パラメータでの受信にも対応しています)。

### デザイン確認モードの補助機能

`designPreviewMode: true` のあいだ、各画面の下に「デザイン確認ツール」が表示されます(本番では表示されません)。

- タイマー表示の切り替え(残り 10 分・5 分・1 分・超過)… 30 分待たずに警告表示と超過表示を確認できます。
- 次回の送信を失敗させる … 送信失敗画面と再送信を確認できます。
- 受験データを消して最初から

## 制約事項

- 受験途中のデータはブラウザの localStorage にあるため、**同じ端末・同じブラウザ**でしか再開できません。シークレットウィンドウやブラウザのデータ削除では失われます。
- 時間は受験者の端末の時計で計測します。端末の時計を変更すると表示・記録がずれます(Apps Script の受信日時を照合に使えます)。
- ログイン機能はありません。氏名は自己申告で(同姓同名は区別できません)、同じ人が複数回受験することも防ぎません(行が増えるので確認者は把握できます)。
- 公開ページは URL を知っていれば誰でも開けます。問題文は閲覧可能で、Web アプリ URL に直接データを送ることも技術的には可能です。厳密な本人確認や不正防止が必要な試験には向きません。
- 記述式は自動採点しません。
- Apps Script の無料枠の範囲で動作します(小規模な社内利用を想定。多数が同時に提出すると数秒待たされることがあります)。
